ONE REAL ERGONOMIC SUGGESTION (would have saved me an hour of confusion)
════════════════════════════════════════════════════════════════════════════

detectChallenge(page) is a bare snapshot. On SPAs that build the widget after
hydration (Bright Data: ~15s!) it legitimately returns {type:null} — which looks
identical to "no captcha here." I spent real time chasing a non-existent
selector bug. Suggest:

    await page.detectChallenge({ wait: true, timeout: 20000 })
    // polls until a widget appears (or timeout), instead of a one-shot snapshot

and in waitForCaptchaToken's auto path: when detectChallenge is null, poll all
WIDGETS for appearance BEFORE falling back to WIDGETS[0] (recaptcha). Right now
a null detection immediately assumes recaptcha and looks for the wrong token
field. Same fix, one place.

Hardening nit (optional): make scriptLoaded authoritative on the window object —
  turnstile : typeof window.turnstile  !== 'undefined'
  recaptcha : typeof window.grecaptcha !== 'undefined'
  hcaptcha  : typeof window.hcaptcha   !== 'undefined'
  arkose    : typeof window.Arkose     !== 'undefined'
  awswaf    : !!window.awsWafCookieDomainList
A src scan can race; window.turnstile cannot lie.

Also: detectChallenge returns only found[0]. On this page a userway iframe
(accessibility overlay) coexists with the widget — returning ALL matches, or
excluding known-noisy iframes, would be friendlier.
